# 项目背景

本项目来源于 AI 提效团队对“业务 Agent 如何持续获得最新知识”的讨论。

现有业务 Agent 已经可以读取飞书知识并回答问题。对于已绑定知识库中的新增、修改和删除，平台是否会自动、及时更新 Agent 的检索结果，目前仍需通过实际测试确认。

项目因此分成三个问题：先验证知识库平台自身的绑定与索引能力；再验证上游采集范围和运行成本是否可控；最后针对会议、Meegle、Base 和上游文档等知识库外部来源，建设一份全局维护、按 Agent 配置运行的知识同步 Skill，使多个业务 Agent 复用同一套候选发现、筛选、审核和沉淀流程。

公司每天在飞书中产生大量会议、妙记、文档和项目记录，因此本项目不建设企业内容全量扫描器。上游发现采用“主动投递和专用业务视图为主、受限增量扫描为辅”：个人工作文档默认排除，先使用元数据、变更记录和业务规则做低成本筛选，只对少量候选读取正文并调用模型提炼。

项目不建设新的问答检索链路，也不建设一个替代全部业务 Agent 的中央知识 Agent。如果三项知识库验证通过，正式知识库内部的普通人工编辑不进入同步 Skill。动态状态继续以 Base 和 Meegle 为权威来源；只有尚未进入目标知识库的稳定事实、决策、规则、流程和复盘结论才进入知识沉淀流程。多 Agent 共用同一来源时，后续采用一次采集、缓存复用、分别路由，避免重复读取和重复消耗 Token。
