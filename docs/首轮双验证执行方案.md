## 1. 本轮要回答的两个问题

两项验证并行进行，但必须分别记录结论：

| 验证 | 要回答的问题 | 本轮不回答的问题 |
|---|---|---|

| B：首轮 MVP 功能链路 | 3—5 份明确提交的会议材料，能否经过范围校验、候选识别、人工审核，形成可追溯的知识提案 | Skill 是否已经产生业务效果、能否自动全量扫描或直接写正式知识 |

本轮先验证“链路能不能正确、安全地工作”，功能通过后再建立业务效果评测集。

## 3. 执行前检查

- [ ] 测试 Bot 是独立实例，不是正式品牌人像判官。
- [ ] 测试知识目录可新建、修改、移动和撤权，且不包含正式业务知识。
- [ ] 记录 Bot 当前绑定范围、管理员、所有者和现有刷新/周任务机制。
- [ ] 验证窗口不跨越未知的周任务；如不可避免，记录任务实际触发时间。
- [ ] 3—5 份会议材料由负责人明确提交或批准，不使用公司全空间搜索。
- [ ] 目标知识目录及文档不出现在上游来源清单中。
- [ ] 首轮使用 `scan --dry-run` 或隔离审核仓，不自动写正式知识。

任一项不满足，先补环境，不以放宽边界继续测试。

## 4. 验证 A：Phase 0

详细记录表见 [知识库绑定行为验证](知识库绑定行为验证.md)。本轮按以下顺序执行：

1. **修改**：先确认 Bot 能检索测试文档 V1，再把唯一标识和正文改为 V2；在立即、5、15、30 分钟观察回答与引用。
2. **新增**：在已绑定测试目录新建含唯一标识的文档，不重新绑定、不重新发布；按相同观察点提问。
3. **失效**：对已可检索的测试文档执行删除、移出目录或撤权；检查旧内容何时不再被引用。
4. 每轮提问要求 Bot 重新读取知识库，保存时间、回答、引用和截图。
5. 测试期间不手动刷新、重绑或重发 Bot；如果执行了任何动作，必须作为变量记录并重新跑一轮。

判定重点：平台原生索引与 Bot 自带的定时/刷新任务必须分开。只有在不依赖额外任务时通过，才能认定目标知识库内部变化由平台处理。

## 5. 验证 B：首轮 MVP 功能链路

当前试点链路：

```text
会议提炼 Agent 输出或明确提交的会议纪要
→ 知识增量维护 Skill 做范围校验、筛选和去重
→ 生成品牌人像判官知识候选
→ 人工审核
→ 本轮只记录是否应沉淀；未经单独批准不写正式知识
```

执行步骤：

1. 在 [单 Agent MVP 评测卡](MVP评测卡.md) 登记 3—5 份真实会议材料及授权证据。
2. 样本至少覆盖：明显相关、夹杂相关与无关内容、明显无关、冲突/待确认、权限或范围边界；不足 5 份时可在同一材料中标注多个预期片段。
3. 只把这些明确 Token/链接列为本轮来源；不启用公司搜索、个人空间扫描或动态定时任务。
4. 严格校验配置后运行 `scan --dry-run`，核对实际读取范围、预算和预计候选。
5. 预演通过后，使用本地审核仓或隔离测试 Base 运行一次正式 `scan`，只生成待审核提案。
6. 高佳先按预期标签记录结果，田海江逐条判定“应保留/应拒绝/需修改/证据不足”。
7. 使用相同输入再运行一次，检查是否出现重复提案或范围扩大。
8. 汇总漏检、误收、冲突、权限、抽取和幂等问题，不以增加扫描量掩盖问题。

首轮通过条件：零越权、零目标自循环、零自动正式写入；范围与预算可解释；相关候选能被发现；无关、未确认和冲突内容能被拒绝或明确标记；第二次运行不重复生成。

## 6. 第一轮之后再决定的事项

| 待决策项 | 需要的证据 | 决策原则 |
|---|---|---|
| 触发优先级 | 哪些来源更新频繁、漏检成本高、人工提交是否足够 | 主动投递优先，再考虑明确事件/人员/关键词 |
| 动态扫描周期 | 单轮新增量、审核负担、时效要求和运行成本 | 不先拍固定周期；从手动或小范围事件触发开始 |
| 是否增加权限 | 当前权限造成的明确阻塞及最小缺口 | 只增加完成已批准测试所需的最小权限 |
| 是否进入正式评测集 | 两条功能链路的真实结果和失败分类 | 功能验证通过后再测业务效果，不把链路测试冒充效果评测 |

## 7. 本轮产出与结论模板

执行结束后必须留下：

- Phase 0 三项结果、首次生效时间、平台/定时任务归因和证据链接。
- 3—5 份样本的预期标签、实际候选、人工审核结果和失败分类。
- 两次运行的范围、预算、提案数和重复情况。
- 一页结论：继续、收紧范围、修配置/代码，或因权限/平台行为阻塞。
- 下一轮是否准备不少于 10 条正例并覆盖反例、边界、冲突和替代样例。
