# Agent 上游采集范围与成本验证

## 1. 验证目的

本验证是 Phase 0.5，位于真实单 Agent 写入之前，可与“知识库绑定行为验证”并行。目标是证明首个 Agent 的上游来源少量、明确、可解释、权限合规且成本可控，而不是把公司飞书内容当作待扫描语料库。

本验证不评估目标知识库的索引能力；该部分见 [知识库绑定行为验证](知识库绑定行为验证.md)。

## 3. 来源准入清单

每个来源都必须有业务目的、负责人和固定范围。个人文档只有主动提交、进入指定共享目录或被明确批准时才能列入。

| 来源类型 | 来源名称 | 固定范围或查询 | 准入方式 | 负责人 | 权威等级 | 是否包含个人文档 | 业务目的 | 结论 |
|---|---|---|---|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 主动投递 / 专用视图 / 受限扫描 | 待填写 | 待填写 | 否 / 已明确批准 | 待填写 | 待确认 |

准入硬规则：

1. 不允许公司全空间或全项目扫描。
2. 文档搜索必须同时限定上游共享目录和关键词；明确 Token 只用于主动提交或负责人批准的文档。
3. 会议或妙记至少配置业务关键词，并叠加参与人、所有者或固定妙记范围。
4. Base 和 Meegle 的稳定知识来源必须使用“待沉淀”“已确认决策”“已完成复盘”等专用视图或 MQL。
5. 目标知识目录、目标知识文档和未经授权的个人文档读取数必须为 0。
6. 日常增量和一次性历史补录分开运行、分开审批预算。

## 4. 当前实现与剩余边界

当前版本已经实现：

- Agent 角色与输出契约、来源准入与权威元数据的配置校验。
- 目标/来源不重叠、文档目录、会议人员范围、搜索相关性和稳定专用视图硬校验。
- 来源 API、元数据、正文、总字符、候选、提案和运行时长硬预算。
- `scan --dry-run` 零持久化写入预演；超限不提交游标。

仍未实现：全面来源侧元数据增量、模型语义提炼、模型 Token 硬预算、自动版本冲突治理和跨 Agent 共享缓存。部分来源可能在服务端返回正文或分页记录后再由本地预算截断，因此仍须使用隔离测试 Base 或 `review.storage: local`，不得扩大到公司级或多 Agent 自动扫描。

Phase 0.5A 先验证来源准入、非模型预算、零越权和预演漏斗；Phase 0.5B 在语义模型接入后复测 Token、事实/结论/推断和提案质量。模型未启用时 Token 填写“未启用”，不能填写为 `0`。

## 7. 通过标准

- 100% 来源通过准入检查，未经授权的个人文档、目标知识目录和目标文档读取数均为 0。
- 不少于 10 条预期样例中至少发现 8 条。
- 首轮“已批准或仅需小修改”的提案占比不低于 60%。
- 动态项目状态、未确认草稿和无关个人内容进入长期知识的数量为 0。
- 相同增量第二次运行不新增重复提案。
- 单次运行不超过已批准预算；超限内容能够停止并安全顺延。
- Phase 0.5A 的来源范围、非模型预算和安全指标通过后，才允许进入隔离提案验证。
- 模型接入后必须完成 Phase 0.5B 的 Token、事实/结论/推断和提案质量测量；“未启用”不等于语义阶段通过。

## 8. 决策记录

| 判断 | 处理方式 |
|---|---|
| 范围、成本和质量全部通过 | 进入单 Agent MVP |
| 来源范围过宽 | 收紧目录、视图、会议范围、人员或关键词后重测 |
| 正文或 Token 超预算 | 增加元数据筛选、摘要优先或分块增量后重测 |
| 提案质量不足 | 优化相关性与稳定知识规则，不通过增加扫描量补偿 |
| 出现个人文档、目标知识或越权内容 | 立即停止，修复配置与代码级拦截后重新验证 |
| 当前代码限制影响结论 | 先补齐对应硬限制，再进入多 Agent 或自动运行 |
