# Agent 上游采集范围与成本验证

## 1. 验证目的

本验证是 Phase 0.5，位于“知识库绑定行为验证”之后、真实单 Agent MVP 之前。目标是证明首个 Agent 的上游来源少量、明确、可解释、权限合规且成本可控，而不是把公司飞书内容当作待扫描语料库。

本验证不评估目标知识库的索引能力；该部分见 [知识库绑定行为验证](知识库绑定行为验证.md)。

## 3. 来源准入清单

每个来源都必须有业务目的、负责人和固定范围。个人文档只有主动提交、进入指定共享目录或被明确批准时才能列入。

| 来源类型 | 来源名称 | 固定范围或查询 | 准入方式 | 负责人 | 是否包含个人文档 | 业务目的 | 结论 |
|---|---|---|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 主动投递 / 专用视图 / 受限扫描 | 待填写 | 否 / 已明确批准 | 待填写 | 待确认 |

准入硬规则：

1. 不允许公司全空间或全项目扫描。
2. 文档搜索必须同时限定上游共享目录和关键词；明确 Token 只用于主动提交或负责人批准的文档。
3. 会议或妙记至少配置业务关键词，并叠加参与人、所有者或固定妙记范围。
4. Base 和 Meegle 的稳定知识来源必须使用“待沉淀”“已确认决策”“已完成复盘”等专用视图或 MQL。
5. 目标知识目录、目标知识文档和未经授权的个人文档读取数必须为 0。
6. 日常增量和一次性历史补录分开运行、分开审批预算。

## 4. 当前 V2 限制

当前版本可以在隔离、小范围配置下完成验证，但不能把以下目标能力当成已实现：

- 部分来源仍会先读取正文或分页数据，再做哈希与规则筛选，尚未全面实现元数据优先。
- 相关性判断仍是关键词、人员和项目字符串匹配，候选正文是截取后的来源内容；同步脚本尚未调用模型进行语义判断和知识提炼。
- 只有单条候选字符上限，尚无单次正文总量、候选数量、模型 Token、运行时长和 API 次数的代码级硬停止。
- 文档目录、相关性条件、来源与目标不重叠等边界尚未全部由配置解析器强制校验。
- 当前没有正式 `dry-run` 和跨 Agent 共享采集缓存。

因此本次验证使用隔离测试 Base 或 `review.storage: local`，严格缩小来源，并人工记录尚未自动统计的指标。未补齐硬限制前，不得扩大到公司级或多 Agent 自动扫描。

当前未启用模型时，模型候选与 Token 字段填写“未启用”，不能填写为 `0` 并据此判定成本验证通过。此时只能先通过“来源范围准入”；接入模型后必须复测 Token、提案质量和审核通过率，才算完成 Phase 0.5。

## 7. 通过标准

- 100% 来源通过准入检查，未经授权的个人文档、目标知识目录和目标文档读取数均为 0。
- 不少于 10 条预期样例中至少发现 8 条。
- 首轮“已批准或仅需小修改”的提案占比不低于 60%。
- 动态项目状态、未确认草稿和无关个人内容进入长期知识的数量为 0。
- 相同增量第二次运行不新增重复提案。
- 单次运行不超过已批准预算；超限内容能够停止并安全顺延。
- 模型已实际启用并完成 Token 与提案质量测量；“未启用”不等于通过。

## 8. 决策记录

| 判断 | 处理方式 |
|---|---|
| 范围、成本和质量全部通过 | 进入单 Agent MVP |
| 来源范围过宽 | 收紧目录、视图、会议范围、人员或关键词后重测 |
| 正文或 Token 超预算 | 增加元数据筛选、摘要优先或分块增量后重测 |
| 提案质量不足 | 优化相关性与稳定知识规则，不通过增加扫描量补偿 |
| 出现个人文档、目标知识或越权内容 | 立即停止，修复配置与代码级拦截后重新验证 |
| 当前代码限制影响结论 | 先补齐对应硬限制，再进入多 Agent 或自动运行 |
