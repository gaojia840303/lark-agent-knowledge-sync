# MVP 运行说明

> 当前首轮试点以 [首轮双验证执行方案](首轮双验证执行方案.md) 为入口：Phase 0 与 3—5 份会议材料的功能链路并行。测试 Bot、权限和运行位置按 [测试 Agent 接入与交接清单](测试Agent接入与交接清单.md) 确认。

## 1. 当前首轮试点

| 项目 | 当前选择 | 状态 |
|---|---|---|
| Phase 0 测试对象 | 品牌人像判官独立测试实例 | 待耿梦桥提供并确认 |
| MVP 上游 | 会议提炼 Agent 输出或负责人明确提交的 3—5 份会议材料 | 待高佳登记 |
| MVP 下游 | 品牌人像判官知识候选 | 待确认知识范围 |
| 人工审核 | 田海江 | 待确认 |
| 运行方式 | 手动触发、先 `dry-run`，再进入本地或隔离审核仓 | 已确定 |
| 正式知识写入 | 首轮不执行，除非另行逐条批准 | 已确定 |
| 动态触发/扫描周期 | 第一轮结果后再定 | 待决策 |
| 生产身份与额外权限 | 只记录最小缺口，不在首轮预先扩大 | 待实测 |

“高佳 Owner 身份”只可作为试验候选身份，不能自动等同于生产运行身份或全部来源的业务授权。

## 2. 并行完成知识库绑定边界测试

按 [知识库绑定行为验证](知识库绑定行为验证.md) 限时完成以下三项测试；它可与配置、来源清单和样例准备并行，但生产启用前必须有结论：

1. 已绑定文档内容修改测试。
2. 绑定目录新增文档测试。
3. 文档删除、移出目录或撤权测试。

记录每项测试的真实结果和首次生效时间，并区分平台原生索引、Agent 问答时重新读取和现有刷新/周任务。三项在没有额外任务干扰时全部通过，目标知识库内部变化才不进入同步 Skill；任何一项失败时，先形成索引、绑定、缓存或权限问题，不使用知识提案流程补偿。

## 3. 完成采集范围与成本验证

按 [Agent 上游采集范围与成本验证](采集范围与成本验证.md) 为候选 Agent 建立来源清单和单次预算：

1. 首轮只配置 3—5 份负责人明确提交或批准的会议材料，不通过搜索扩大样本。
2. 后续优先配置“待沉淀”共享目录、知识候选 Base，以及 Base/Meegle 的专用业务视图。
3. 受限扫描只允许明确的会议系列、关键词、人员、项目和共享目录。
4. 不扫描公司全空间；个人文档默认排除，只有主动提交或明确批准时才能进入来源。
5. 文档搜索必须同时配置上游共享目录和关键词。
6. Base、Meegle 的稳定知识来源必须使用专用视图或 MQL，不整表、整项目读取。
7. 明确单次元数据、正文、候选、Token、提案和运行时间上限，超限内容顺延。

当前代码已强制来源 API、元数据、正文、候选、提案和时长预算，并支持 `dry-run`。尚未实现真正的模型语义提炼、模型 Token 预算、全面来源侧增量、自动版本冲突治理与共享采集缓存。首个 MVP 仍只能使用隔离测试仓和严格小范围配置。

模型未启用时先完成 Phase 0.5A 的来源范围、非模型预算和安全验证，Token 字段填写“未启用”。语义模型接入后再完成 Phase 0.5B 的 Token、事实/结论/推断和提案质量验证。

## 4. 准备配置

复制根目录配置模板：

```powershell
Copy-Item .\agent-sync.example.yaml .\agent-sync.yaml
```

在 `agent-sync.yaml` 中补齐：

1. Agent ID、名称、负责人、角色、职责、决策范围、输出契约和成功指标。
2. 公共、专属知识目录及目标文档 Token。
3. 首轮 3—5 份明确提交的会议/文档 Token；后续再配置主动投递入口、妙记范围、上游共享文档目录、Base 专用视图和 Meegle 专用视图或 MQL。
4. 每类实际来源的准入方式、来源负责人、业务目的和权威等级。
5. 相关人员、项目、包含词、排除词和审核人；搜索型来源不得把所有相关性规则留空。
6. 来源 API、元数据、正文、候选、提案和运行时长预算。
7. 本地审核仓，或隔离测试 Base 与三个管理表 ID。

`agent-sync.yaml` 已被 Git 忽略。不得在其中保存 API Key、访问令牌、Cookie 或其他凭证。

上游文档只能配置目标知识库之外的文档。`knowledge.public_document_token` 和 `knowledge.private_document_token` 不得再次出现在 `sources.documents.document_tokens` 中。

运行 `validate-config --strict` 会检查 Agent 契约、来源治理字段、文档目录、稳定视图和目标/来源重叠；人工仍须确认来源授权真实有效，个人文档准入有证据，业务目的和权威等级正确。

## 5. 初始化审核仓

首轮优先使用 `review.storage: local`；需要多人共同审核时，再使用隔离测试 Base：

```powershell
python scripts/sync.py bootstrap-base --name "Agent 知识同步管理-测试"
```

将返回的 Base Token 和三个表 ID 只写入本机 `agent-sync.yaml`，不得提交 Git。

## 6. 隔离环境运行

```powershell
python scripts/sync.py validate-config --config .\agent-sync.yaml --strict
python scripts/sync.py scan --config .\agent-sync.yaml --dry-run
python scripts/sync.py scan --config .\agent-sync.yaml
python scripts/sync.py status --config .\agent-sync.yaml
python scripts/sync.py apply --config .\agent-sync.yaml --proposal-id "<proposal-id>"
```

首轮执行顺序：

1. 先运行严格配置校验。
2. 运行 `scan --dry-run`；它读取配置允许的受控来源，但不写提案、运行记录或游标。
3. 对照 3—5 份样本清单，确认读取范围、预算和预计候选无误。
4. 预演通过后，使用本地审核仓或隔离测试 Base 运行正式 `scan`，只生成待审核记录。
5. 田海江逐条给出保留、修改、拒绝或证据不足意见。
6. 相同输入再运行一次，验证不重复生成且范围没有扩大。
7. 首轮不执行 `apply`；如确需验证写入，须另行批准并只写独立测试文档。

运行结果自动记录非模型漏斗；模型未启用时 Token 记录为“未启用”。

## 7. 在线执行器与调度

```powershell
$env:AGENT_SYNC_CONFIG_DIR = '<Agent 配置目录>'
$env:AGENT_SYNC_WEBHOOK_SECRET = '<至少 24 个字符的随机密钥>'
python scripts/server.py --host 127.0.0.1 --port 8765
```

执行器只读取服务器上的 Agent 配置，HTTP 请求不能覆盖数据源或写入目标。

第一轮结果前不启用在线执行器、周调度或动态扫描。结果出来后，再根据新增量、漏检成本、审核负担和时效要求决定“主动投递、事件触发、人员/关键词触发或定时扫描”的优先级。

如果后续飞书自动化无法调用 HTTPS，可以增加：

```text
--weekly --weekly-weekday 0 --weekly-time 09:00
```

该配置仅表示按服务器本地时间在每周一 09:00 运行全部 Agent 配置，不是本轮默认方案。只有知识库边界结论、Phase 0.5 和单 Agent MVP 均通过后才能启用。调度周期与 `lookback_days` 是两个独立参数。

## 8. MVP 验收

完整样例、失败分类、业务结果反馈和放行规则见 [单 Agent MVP 评测卡](MVP评测卡.md)。

### 首轮功能验证

1. Phase 0 三项行为都有真实结果、生效时延和刷新/定时任务归因。
2. 3—5 份会议材料都有授权、预期标签、实际候选和人工审核结果。
3. 公司全空间、未经授权个人文档、目标知识目录和目标知识文档读取数为 0。
4. 未确认讨论、动态状态和冲突内容不被直接写成正式知识。
5. 相同输入第二次运行不重复生成；首轮不自动写正式知识。
6. 第一轮结果足以支持触发优先级、扫描周期和最小权限决策。

### 正式质量与业务验收

1. 功能验证后扩充到不少于 10 条正例，并覆盖反例、边界、冲突和替代样例。
2. 不少于 10 条预期正例中至少发现 8 条，首轮“批准或仅需小修改”的提案不低于 60%。
3. 单次运行不超过已批准的正文、候选、Token、提案和时长预算；超限内容能够停止并安全顺延。
4. 未批准或已拒绝提案不能写入正式知识，同一批准提案重复应用不会重复写入。
5. 连续运行 2—3 个真实周期通过后，再用固定品牌人像任务评估正确性、引用质量、人工修改量或完成时间。
