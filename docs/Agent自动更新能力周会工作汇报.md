# Agent 关键知识维护与供给｜阶段工作汇报

> 汇报日期：2026-07-29
> 当前阶段：单 Agent MVP 准备与双验证并行
> 一句话结论：项目定位、来源治理、非模型硬预算和零写入预览已经落到代码；下一步不是继续扩能力，而是选定一个 Agent，用真实样例完成边界、成本和业务效果验证。

## 一、项目目标

建设一套供多个业务 Agent 共用、范围和成本可控的关键知识维护与供给能力：

- 先明确每个 Agent 的角色、职责、决策范围、输出契约和成功指标，再反推允许进入流程的知识来源。
- 在每个 Agent 明确授权的高价值来源内，以主动投递和专用业务视图为主、受限增量扫描为辅，发现值得沉淀的信息。
- 先用元数据、变更记录和业务规则低成本筛选，只对少量候选读取正文；模型语义提炼属于后续能力，不冒充当前现状。
- 经人工审核后，写入对应 Agent 的公共或专属知识目录。
- 每个 Agent 使用独立配置，共用一份 Skill，避免重复开发和知识串库。

本项目不扫描公司全部飞书内容，不默认扫描个人工作文档，不重做 Agent 的问答检索能力，也不复制 Meegle、Base 中持续变化的项目状态。

## 三、落地步骤

1. **Phase 0：限时验证知识库原生感知能力**
   分别测试修改、新增、删除或撤权；与代码加固和 MVP 准备并行，但结果落定前不启用生产调度。

2. **Phase 0.5：验证来源与成本漏斗**
   为首个 Agent 建立来源清单和权威等级，先运行严格校验与 `dry-run`，证明个人文档、目标知识和无关来源读取数为 0。

3. **Phase 1：单 Agent MVP**
   在隔离小范围内按“预览—扫描—审核—应用—评测”跑通闭环，连续运行两次验证幂等，并衡量实际业务输出是否改善。

4. **Phase 2—3：语义、生命周期、多 Agent 与自动运行**
   补齐模型提炼与 Token 预算、冲突/过期/替换治理、全面来源侧增量和共享缓存后，再扩展多 Agent 并上线自动运行。

## 四、预计卡点

| 卡点 | 可能影响 | 应对方式 |
|---|---|---|
| 知识库更新是否会自动生效尚未验证 | 无法准确判断 Skill 是否需要处理目标知识库内部变化 | 先完成三项黑盒测试，并明确可接受的生效时限 |
| 飞书内容量大且个人文档噪音高 | 全量筛查会造成 Token、权限和审核成本失控 | 默认不做全量扫描，个人文档默认拒绝，采用主动投递、专用视图和受限扫描 |
| 部分来源尚未做到完整来源侧增量 | 服务端可能先返回正文或分页结果再由本地预算截断 | 首个 MVP 使用隔离来源和专用视图；记录 API、元数据和正文漏斗，不扩大目录或时间窗 |
| MVP 业务配置尚未齐备 | 无法进入真实数据验证 | 确认 Agent、负责人、审核人、数据源、目标目录和 10 条样例 |
| 模型语义提炼与 Token 预算尚未实现 | 当前候选质量主要依赖范围与规则，不能验证最终提炼质量 | 先验证来源和规则漏斗；模型接入后单独复测事实、结论、推断和 Token 成本 |
| 用户身份授权不适合长期自动运行 | Token 失效会导致定时任务中断 | 生产阶段改用应用身份或专用服务账号，并验证自动刷新 |
| 知识提炼准确率和审核工作量未知 | 提案过多或质量不稳会增加人工负担 | 先测候选漏斗和审核通过率，再接入真正的模型提炼，之后逐步放开低风险自动化 |

## 五、待解决问题

本周优先确认以下事项：

1. 选定首个 MVP Agent，写清它的实际业务输出、负责人、审核人和成功指标。
2. 选一个测试 Agent 与目录并完成限时绑定行为测试；同时定义“可接受”的索引生效时限。
3. 确定首个 Agent 的主动投递入口、专用视图、白名单来源、权威等级和单次预算。
4. 如品牌六要素和产品五张牌同时满足条件，默认选择品牌六要素 Agent。
5. 补齐真实来源、目标文档、负责人、审核人和不少于 10 条预期变更样例。
6. 在隔离配置上依次完成严格校验、`dry-run`、首轮扫描、审核、应用和结果评测。

## 六、下一阶段完成标志

- 三项知识库绑定行为测试有明确结论，Skill 边界最终确认。
- 采集范围与成本验证通过，公司全空间、个人文档和目标知识的越界读取数为 0。
- 单 Agent MVP 配置与来源清单准备完成，并成功生成首批可追溯的真实知识提案。
- 不少于 10 条预期样例中至少发现 8 条，首轮“批准或仅需小修改”的提案不低于 60%。
- 相同内容连续运行两次不重复，且运行未超过批准的正文、候选、Token 和时长预算。
- 至少一个 Agent 的实际业务输出指标有基线和运行后结果，不只统计提案数量。
