# Agent 知识库绑定行为验证｜一次性边界测试

## 1. 验证目的

确认 Agent 已绑定知识库发生变化后，知识平台是否会自动更新检索结果。验证结论只用于裁决“链路 A：目标知识库内部变化”由平台还是额外机制负责。

本测试可与上游链路的代码加固、Source Manifest 和 MVP 样例准备并行，不阻塞这些工作；它阻塞的是生产自动运行，以及把目标知识库内部变化正式排除出项目职责。

本验证只测试知识库平台的绑定、索引、缓存和权限传播能力，不测试上游知识提炼流程。

## 3. 统一测试规则

1. 使用独立测试 Bot、独立测试目录和测试文档，不修改正式业务知识；首轮只测 Wiki/文档，不混入 Base 数据变化。
2. 每项测试使用唯一标识，例如 `KB-UPDATE-20260717-001`，避免模型凭常识猜中答案。
3. 提问时要求 Agent 重新读取知识库，并返回唯一标识、对应正文和引用来源；不得把历史对话记忆当作检索结果。
4. 分别在变更后立即、5 分钟、15 分钟和 30 分钟测试，记录首次正确生效时间；如果平台已有明确 SLA，可按 SLA 调整观察点。
5. 每次测试保留提问、回答、引用来源、时间和必要截图。
6. “感知成功”不要求 Agent 主动通知，只要求它在问答检索时使用变化后的有效内容。
7. 测试窗口内不得手工刷新索引、重新绑定、重新发布或重发 Agent；如发生，必须记录动作和时间，并把该轮标记为“受干扰”。
8. 先记录 Bot 是否已有“每次重新读取”、知识刷新、周任务或其他定时任务。尽量避开其触发窗口；若无法避开，必须把平台原生行为和任务触发后的行为分开记录。
9. 本测试不证明上游同步 Skill 有效，也不把已有周任务等同于平台原生自动索引。

## 4. 测试一：已绑定文档内容修改

### 操作步骤

1. 在已绑定测试文档写入唯一标识 `KB-UPDATE-V1-<时间戳>`，先确认 Agent 能正确检索。
2. 将正文和唯一标识改为 `KB-UPDATE-V2-<时间戳>`，并完全删除 V1 内容。
3. 使用相同问题分别在各观察点询问 Agent。
4. 检查回答是否引用 V2，是否仍引用已经删除的 V1。

### 通过标准

- 在约定时延内返回 V2 内容及正确来源。
- 不再把 V1 当作当前有效知识回答。

## 5. 测试二：绑定目录新增文档

### 操作步骤

1. 在已经绑定的测试目录中新建文档，不手工调整 Agent 绑定配置。
2. 写入唯一标识 `KB-NEW-DOC-<时间戳>` 和无法通过其他来源推断的测试事实。
3. 在各观察点询问该测试事实。
4. 检查 Agent 是否自动纳入新文档并返回正确引用。

### 通过标准

- 无需重新绑定或重新发布 Agent。
- 在约定时延内返回新文档内容及正确来源。

## 6. 测试三：文档删除、移出目录或撤权

### 操作步骤

1. 新建仅用于本测试的文档，写入唯一标识 `KB-REMOVED-<时间戳>`，先确认 Agent 能检索。
2. 将文档删除、移出绑定目录或撤销 Agent 权限，记录具体操作类型和时间。
3. 在各观察点继续询问唯一标识对应内容。
4. 检查 Agent 是否仍引用失效文档或缓存内容。

### 通过标准

- 在约定时延内不再将失效文档作为可引用知识。
- 回答中不再提供失效文档引用。

## 8. 决策记录

| 判断 | 处理方式 |
|---|---|
| 三项在无额外刷新/定时任务情况下全部通过 | 目标知识库内部变化由知识库平台处理，不进入同步 Skill、审核表和游标表 |
| 只有刷新或周任务触发后通过 | 不能判定平台原生自动处理；记录触发机制、时延与责任人，再决定是否保留现有刷新任务 |
| 修改测试失败 | 建立索引刷新或缓存问题，不用知识提案流程补偿 |
| 新增测试失败 | 评估目录绑定、文档注册或 Agent 重新发布机制 |
| 删除测试失败 | 优先修复失效索引、缓存或权限同步，未解决前不得依赖自动删除生效 |

最终结论：**待测试后填写。**

本验证通过只说明目标知识库内部变化可以由知识平台处理，不代表可以全量扫描外部飞书内容。无论结果如何，上游来源仍须执行 [Agent 上游采集范围与成本验证](采集范围与成本验证.md)。

如果测试尚未完成，可以继续配置校验、预算、`dry-run`、来源清单和评测集；在结果落定前不得启用生产调度，也不得用同步 Skill 扫描目标知识库补偿未知行为。

首轮的统一执行顺序、角色和结论模板见 [首轮双验证执行方案](首轮双验证执行方案.md)。
