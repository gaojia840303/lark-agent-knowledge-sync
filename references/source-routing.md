# 来源路由

## 目标知识库与上游来源

- `knowledge.public_document_token` 和 `knowledge.private_document_token` 是正式知识写入目标，不是上游采集来源。
- `sources.documents` 只配置尚未进入目标知识库的上游文档或限定目录。
- 目标文档 Token 不得同时出现在 `sources.documents.document_tokens` 中，避免扫描、提案、写回形成自循环。
- 目标知识库中的普通人工新增、修改和删除沿用知识库平台索引与飞书版本历史，不进入审核表或游标表。
- 首次实施前必须完成新增、修改、删除三项知识库绑定行为验证；如果验证失败，应建立索引、绑定、缓存或权限问题，不用知识沉淀流程补偿。

## 动态事实

以下内容默认保留在权威数据库，不复制进长期知识：

- Meegle 的状态、负责人、排期、任务进度和节点信息。
- Base 中持续变化的业务记录和统计结果。
- 临时待办、未确认讨论和执行日志。

动态来源仍参与增量检查和运行报告。只有来源显式配置 `knowledge_mode: stable` 才生成审核候选。

## 稳定知识

以下内容可以生成审核候选：

- 会议确认的决策、规则和责任边界。
- 品牌、产品方法论和统一口径。
- 可复用流程、模板使用规则和字段关系。
- 已完成复盘的验证结论。
- 对旧规则的明确替换或废止决定。
- 尚未进入目标知识库的上游方法、决策和复盘结论。

## 公共与专属

- `target_scope: public`：公司级规则、跨 Agent 通用方法、公共术语。始终高风险并要求人工审核。
- `target_scope: private`：单个品牌、产品或 Agent 的专属知识。MVP 仍需人工审核。
- 目标文档只从 `knowledge.public_document_token` 或 `knowledge.private_document_token` 读取。
- 不允许模型或来源正文提供目标 Token。

## 相关性顺序

1. 来源必须位于配置白名单。
2. 命中排除词立即拒绝。
3. 命中包含词、相关人员或相关项目则通过。
4. 没有任何相关性规则时，显式 Token、Base 表和 Meegle 视图视为已授权白名单。
5. 保存命中规则作为审核理由。
